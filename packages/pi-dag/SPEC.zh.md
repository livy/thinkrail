# pi-dag —— 持久的、宿主拥有的编排

> 中文译文，原文见 [`SPEC.md`](./SPEC.md)。英文原文是唯一权威来源，二者不一致时以原文为准。

## 职责（Responsibility）

一个可移植的后端 DAG 服务与 pi 扩展，构建在 [[module-pi-delegation]] 之上，
独立于 `pi-subagents` 和 ThinkRail。Pi 拥有每次模型调用、会话、压缩与用量记录；
本包拥有图调度、持久证据、门禁、命令与恢复。它不被捆绑进 ThinkRail，
也不暴露任何 UI 或 wire 实现。

## 边界（Boundary）

公开包接口：`createDagService`、`createDagExtension`、默认独立扩展，
以及带类型的 command/read/binding 契约。四个读取（`listDags`、`getDag`、`getOutput`、
`listHistory`）和一个 `execute` 派发器构成控制器面。没有原始 AgentSession、检查点 CRUD、
通用查询语言、替代 spawner 或公开的效应引擎。

允许的依赖：经 barrel 访问的 `pi-delegation`、公开的 pi/typebox peer API 和 `node:*`。
禁止：ThinkRail 工作区包、`pi-subagents` 策略、pi 私有字段与兄弟包内部。
内部依赖边是 `extension → runtime + domain + pi-delegation`、
`runtime → domain + persistence + pi-delegation`，以及 `persistence → domain`。
扩展直接使用 domain 的 schema/契约；它的独立组合会创建委托服务，
而它注入的适配器绝不拥有该服务。公开 DTO 是共享类型，不是另一个状态所有者。
worker 工具适配器是运行时本地的，接收窄回调，绝不接收控制器客户端。
每个子模块使用一个 barrel。

## 所有权与执行上下文（Ownership and execution context）

一个 DAG 是一种资源，绝不是伪造的父会话。限定作用域的服务拥有实时执行；
会话绑定只拥有控制/通知的附着。注入的服务仍归宿主所有。ThinkRail 选定的集成策略
是工作区所有权；其他宿主可以通过调用同样的控制来施加会话或服务生命周期策略。
不添加所有权模式调度器。受信的 `owner` 绑定可以执行生命周期控制，但它不是人，
不能批准或绕过仅限人工的放行。无会话构造使用显式的执行上下文。

资源获取会急切保留执行依赖，即使以暂停状态、零 worker 创建时也是如此。
优先使用精确的运行时注入；独立 registry 投影复用委托的不透明 provider 重放。
被保留的对象是借用，而不是冻结或暗中处置。提供方所有者保证它们在其选定生命周期内可用；
不可用的模型/鉴权路径会大声失败，绝不回退或借用最新控制聊天的默认值。
没有一刀切的扩展 provider 禁令。

独立所有者以规范化的 root/scope 为进程根，能在聊天切换后存活，在退出时关闭，
在重载时静默。进程丢失后恢复为暂停；没有模型调用能在宿主退出后存活。
所有者的 `close` 只结算它自己的资源，并保留可恢复的状态与不相关的父级子会话。

## 命令与证据（Commands and evidence）

变更身份是调用方提供的 `commandId`；非创建请求还要给出 `dagId` 和 `expectedVersion`。
凭据查找会先复核其存储的权威，然后在校验或授权替换载荷之前、在版本/目标检查之前去重。
已接受 id 下的载荷若发生变化则失败。重放在触碰新的执行/历史输入之前先恢复原始凭据。
取得进程所有权之后，服务在版本检查之前重新检查凭据，因为先前的所有者可能在被动读取
与其死亡之间完成提交；确定性创建遵循同样的规则。凭据确认的是持久意图，
而不是派发、消费或完成。实际的工具调用 id 是来源证据。预期失败是带类型的结果值；
有歧义的 I/O 要求完全相同的重放。

一个节点拥有不可变的编号尝试；每个尝试拥有一个真实的 pi 会话和编号激活。
continue/answer 复用它；retry 从图选定的输入/历史创建一个新会话。保存出生元数据
与声明式整形，而不是可变的句柄别名或运行时凭据。尝试整形是一个不可变的配置文件；
当前默认值住在定义里，而不是第二份可变 profile。若定义与宿主上下文都未提供，
缺失的 thinking 配置解析为 `off`。委托的出生作用域被逐字保留，
无需等于本服务的存储作用域；资源 id 绑定这两个所有者。
输出、输入答案、决策、已消费输入与历史捕获都是不可变证据。
存储版本与图修订号彼此不同；流式增量不推进存储版本。

单一的、无环的连接集合表达具名数据、控制和显式的 `context: fork`。没有标记意味着 fresh。
每个目的地至多一个继承来的会话基；汇合从不合并会话。节点源 fork 需要已接受的输出/历史放行，
且不允许跳过。主 fork 在首次使用、调用它的工具批次之前捕获一个固定种子；
后续主 fork 复用它。委托拥有规范化的捕获/校验/fork；本服务拥有保留的字节与放行授权。
重试不会隐式 fork 失败的尝试。worker 共享 checkout。

## 结算、门禁与控制（Settlement, gates and controls）

worker 只暴露 `dag_submit_result` 和 `dag_request_input`。受信映射启用精选扩展，
并把这两个工具并入生效的允许列表（在其 64 工具上限之内）。这些调用必须是批次中唯一的工具、
持久记录一个提议/请求，并请求终止；它们不是结算。自动接受要求已结算的 `completed`
加上最终的 `stop`/`toolUse`、有效的显式输出、已满足的门禁和已解决的干预。
错误/长度/中止/缺失的证据从不自动接受。人工接受保留真实结果，且不能绕过门禁。
worker 不批准任何东西。输入请求默认归人工权威；批准门禁显式选择人工或人工加控制器。
取消一个人工输入门禁不会授权削弱其既定策略。不可用的历史捕获会独立于其他方面已授权的
仅输出消费者而阻断 fork 消费者；输出批准无法授权后续的历史导出。
拒绝那次后续导出不会撤销已接受的普通输出。拒绝在其确切的捕获范围内保持权威；
不相关的编辑不会重建同一个门禁。

create 是暂停的。resume 允许准入；pause 停止新准入而不中止正在运行的工作。
interrupt 协作式地停止排队/活动工作并将其留在原地等待继续；cancel 要求重试。
DAG 级控制会让从未准入的节点保持 pending，因为它们没有可继续/重试的尝试；
对这样一个节点的精确 cancel 会被拒绝，并引导调用方使用显式 skip。dispose 是终态的，
但保留可读的历史。restart 恢复为暂停；不确定的派发需要显式核对，证明旧工作已不再存活，
才能 continue/retry。没有盲目重放。

steering 是字面的、仅针对活动调用的且尽力而为的。在提议之前观察到的入队，
可以在运行结算时以 offered 关闭，但绝不作为消费的证明。迟到、被拒绝或不确定的干预
会阻断自动接受，直到更晚的合格提议或显式取代出现。队列清理防止控制泄漏到另一次激活。
答案使用字面的继续，而不是 steering，且永不绕过 pause。所有运行/控制 promise
都在状态队列之外被 await。

编辑是原子化的带类型 put/remove 操作。拒绝会使活动工作失效的改动，直到显式中断结算。
把受影响的已消费尝试标记为 stale，包括暂停/等待中的后代；取代它们的提议/门禁并要求重试。
绝不静默重跑后代。skip 只释放合格的、非 fork 的控制依赖；不伪造具名数据/历史。
策略编辑、skip、人工接受或种子都不能绕过仅限人工的放行。

## 持久化与读取（Durability and reads）

本地按 DAG 的原子快照包含状态/历史/凭据/意图/通知。在引用之前同步不可变载荷；
在 ACK 之前同步/替换快照。每个资源只有一个控制进程，并在变更之前检查排他所有权；
死亡所有者的恢复不是租约到期抢占。读取不声明所有权。它们区分本地、其他/不确定
与非活动所有权；非活动的执行被投影为暂停/不确定而不写入快照。未知/损坏的状态
按失败关闭处理，因此快照 schema 是封闭的：已存储的结果只保留它点名的 run-detail 字段，
而新加入 `DelegationRunDetails` 的字段必须在结算时被剥离，直到 schema 有意采纳它们。
已存储的结果保留子会话生效的 `model` 和可选的 `thinkingLevel`，
`getDag` 在恢复后原样暴露它们。较旧结果中缺失的 effort 保持缺失，
绝不从配置推断。这一可选新增保持了快照 schema 版本 1：较旧的快照仍可读，
但降级到其封闭 schema 早于 `thinkingLevel` 的宿主会拒绝包含该字段的快照。
不提供降级迁移。派发遵循已提交的意图，然后提交观察。未观察到的效应在进程丢失后
保持不确定；不主张恰好一次的外部副作用。失败的提交无法发布推测性的内存状态。

`getDag` 是一个完整的、版本一致的当前图/节点/门禁投影，而不是私有存储。
它包含冻结的已消费输入/配置、继承与导出的捕获来源/放行状态，
以及即使是没有具名输出端口的纯控制节点的接受决策。当前激活的门禁包括它们的处置与决策，
而不仅是待处理的问题。
大体量的不可变内容使用捕获文件，附带身份、SHA-256、字节长度和一个新解析出的路径。
既有文件工具读取它们；`getOutput` 读取具名提议，而不是任意会话记录。
历史分页被版本钉住，默认 20、最多 100；过期游标显式失败。每行历史暴露其不可变事件清单，
外加对其捕获正文的新解析引用，因此历史定义、门禁问题、输出与终态文本仍可访问，
无需按实体查询，也不依赖私有存储布局。

初始准入上限：128 个节点、512 个连接、每节点 32 个端口、128 字节 id、
1 MiB 序列化定义、每个提交值/制品或物化的字面量载荷 16 MiB，以及每次捕获历史 32 MiB。
多个输入也必须落在字面量载荷上限内；对更大的工作集使用制品引用和显式选定的文件工具。
每次激活至多一个当前提议或输入请求是合格的；过去的证据留在历史里。
快照正文使用捕获引用/预览，因此所有已准入的当前身份/拓扑都保持可见。
上限是保守的安全限制，不是对历史工作总量的封顶。它们在变更与捕获边界处校验，
绝不通过静默截断一次读取来执行。

通知是持久的里程碑，被动投递给已附着的空闲会话，并带有就绪唤醒与撤销/相关性复核。
Pi 提交不是持久的会话记录 ACK；DAG 历史仍是权威。没有通知会启动一次模型轮次。

## 可移植的 pi 适配器（Portable pi adapter）

`createDagExtension({ service, executionContext? })` 返回一个基于宿主拥有服务的工厂。
可选的同步投影返回当前显式的资源上下文，而不获取 provider 或校验凭据；
默认的独立投影使用公开的 registry、cwd、模型和 thinking 设置。
命令绑定实际的控制器会话 id 与工具调用边界，保留调用方的
`commandId`/`expectedVersion`，绝不接受模型提供的 actor/session 截取。
一个短时存在的调用信号把工具取消与会话生命周期结合起来。一个独立的仅通知绑定
在会话期间存活；该绑定中不保留执行上下文。

五个控制器工具直接映射到服务：`dag_create`、`dag_edit`、`dag_control`、`dag_decide`
和 `dag_read`。最后一个只在四个具名读取之上提供 `list`、`get`、`output`、`history` 变体。
结果携带完整的结构化 `DagResult` 和保留所有当前身份/拓扑的可读内容；
大体量文本仍为捕获引用。`tool_result` 钩子通过 pi 的公开 `isError` 覆盖标记结构化失败，
而不丢弃它们的细节，也不保留 error-id 暂存。ACK 不是 worker 完成。

`/dag <JSON command request>` 是独立操作者路径：校验同一个请求，要求真实交互式确认，
然后绑定人工权威。拒绝或 UI 不可用则不执行任何命令。控制器工具绝不自我提升为人工权威。
操作者使用当前显式的历史边界；两条路径都不导入任意会话。
宿主代码也可以改为直接通过服务绑定受信的人类。

零配置默认安装同一个适配器，使用以规范化的 agent 存储根与规范化的 cwd 作用域为键的
惰性进程根所有者。版本化的全局 registry（而非模块缓存生命周期）持有所有者。
新建/恢复/fork 关闭原因只撤销旧的会话；重载/退出在替换/退出之前静默所有独立所有者
（包括未显示的作用域）。不兼容的已保留 registry 版本会大声失败，
而不是采纳旧代码的运行时对象。注入的服务绝不被适配器关闭。
仅空闲的被动通知使用 pi 的 `triggerTurn: false` 消息，在 `agent_settled` 时唤醒，
在撤销时解除附着。没有原始会话或第二执行循环被暴露。

## 验证（Verification）

公开接口测试钉住重放/CAS、图校验、门禁与间接权威绕过、stale 等待中的尝试、
不可变输出/历史、fork 扇出、pause/interrupt/cancel/continue/retry、暂停恢复、
不确定派发、所有权互斥、失败提交与被动通知。委托测试拥有 pi 历史机制、
保留的上下文、字面队列与结算屏障。一个聚焦的集成测试使用真实 pi 会话和确定性的本地
provider 行为；默认套件不需要 provider 密钥或付费调用。既有的父级/subagent 测试仍是门禁。
