# 持久 DAG 快照、所有权与不可变载荷

> 中文译文，原文见 [`SPEC.md`](./SPEC.md)。英文原文是唯一权威来源，二者不一致时以原文为准。

## 职责（Responsibility）

拥有每 DAG 的本地快照持久性、独占的进程所有权与不可变的捕获字节。
域拥有快照 schema；运行时拥有转移、证据捕获与发布。

## 边界（Boundary）

- **公开接口：** `createDagStore`、`DagStore`、`DagLease`

barrel 是唯一的同级入口。外部依赖是 `node:*`；领域契约与校验通过其公开 barrel 消费。
不涉及运行时、扩展、委托内部、provider、凭据、网络、通用 I/O 抽象或后台过期服务。

## 存储与围堵（Storage and containment）

构造时解析一个受信任的、配置好的存储根，包括既有的根别名。其下，
SHA-256(scope)/dagId 包含 `state.json`、`payloads/` 与 `owners/`。scope 字符串永不成为路径组件。
DAG id 是安全的有界路径组件。后代目录与文件不得是符号链接；内容必须是普通文件。
文件使用私有权限。根的重定位通过在移动后的根上打开一个新 store 来支持：
持久化的引用只包含摘要与大小，绝不包含绝对路径。文件在发布之前被同步，包含目录在平台允许之处被同步。
Windows 上的 Node/Bun 会以 `EPERM` 拒绝目录 `fsync`；那一个平台结果被容忍，因此原子的 link/rename
仍然适用，但命名空间的掉电持久性不能声称拥有 POSIX 目录屏障。存储树是本地的、由服务管理的，
不是针对一个并发特权行为者在两次调用之间替换其祖先的安全边界。

`read` 恰好打开一个已提交快照并解码它；缺失是 undefined，损坏或未知 schema 是显式错误。
`list` 枚举已提交快照，并忽略外来的不安全名称或非目录的根条目，以及没有快照的目录。
一个安全 id 的符号链接，或一个已提交状态损坏的 DAG 目录，仍然失败关闭。两者都不获取所有权，
也不把私有快照作为公开载荷导出。不维护任何全局资源索引或数据库。

## 所有权（Ownership）

`claim` 用一个独占硬链接发布一条已同步的不可变所有者记录。记录是带格式版本、host、PID 与随机身份
令牌的规范 JSON；非规范编码（包括重复键）是有歧义的，被拒绝。每次获取都在该 DAG 的 `owners/` 中
追加下一条编号记录；释放则发布一个令牌匹配的不可变释放标记。这些小记录被保留，不删除、不压实。
这避免了先比较再 unlink 的竞争：相互竞争的恢复者只能争用同一个下一个槽位，永不删除一个更新所有者的锁。
临时的未发布文件被忽略。未知或不连续的所有权文件名，或格式错误的活跃所有者/释放记录，失败关闭。
已退役的记录没有控制权。另一台宿主上未释放的所有权是有歧义的，会阻止获取。

一个活的 PID —— 包括本进程通过另一个 store —— 会阻止获取。只有 `kill(pid, 0)` 以 ESRCH 失败才证明
一个未释放的所有者已死。EPERM、未知失败与复用的活 PID 都会阻止；年龄从不授权接管。
保存、载荷发布与释放都会重新校验当前令牌。读取对竞争进程仍可用，但 `put` 需要该 store 中一个被准入的
lease。`ownerStatus` 采样所有权而不获取它：已释放/缺失/已证明死亡为 inactive；否则为 held。
运行时读取使用这个事实来区分另一个所有者与暂停的恢复；它是一次观察，不是对随后进程死亡或获取的保证。

同一个 lease 上的并发保存被拒绝。释放会同步关闭准入，等待所有已准入的保存与载荷写入（包括失败的），
然后发布释放。重复释放返回同一份结算。失去所有权永不会授权删除或替换另一个令牌。
一次在发布其所有者记录之后失败的获取，可能保守地保持为已拥有直到进程死亡；
有歧义的元数据永不被自动修复。

## 快照（Snapshots）

保存会在其第一次 await 之前分离并校验传入的状态。Scope 与 DAG id 必须匹配；
创建要求当前没有快照、expectedVersion 为 undefined 且 version 为 1。更新要求 expectedVersion 等于
已提交版本，并且恰好递增一个版本。图 revision 归域所有，独立于本存储的 CAS。每次读写都使用
`decodeState`。

一个可选的同步 `beforePublish` 检查，在异步准备与所有权检查之后、发出原子替换之前的那一刻，
重新校验调用方的撤销。被拒绝的检查清理临时文件而不发布。一旦替换已经被发出，
取消不会回滚一条可能已提交的命令。

快照字节被规范编码进一个独占的临时文件，同步并关闭，然后原子地 rename 覆盖 `state.json`；
包含目录遵循上面的平台规则。挂起的临时文件在失败时被清理。不存在内存状态缓存或推测性发布。
替换之前的错误是确定的失败；替换之后的错误，或有歧义的 rename 错误，是 `commit-unknown`，
需要在运行时边界上做一次读取/相同命令重放。

## 载荷（Payloads）

`put` 在 await 之前分离 Uint8Array 输入。默认配额是 LIMITS.valueBytes；显式配额不得超过
LIMITS.historyBytes。产物身份等于小写的 SHA-256 摘要。字节在独占发布进每 DAG 的载荷目录之前被同步，
该目录的元数据也在返回之前被同步。并发的相同内容去重；既有字节被校验而不是被覆盖。
调用方在保存引用之前 await `put`；快照校验不递归加载所有历史载荷。

`load` 校验引用身份、字节长度与摘要。缺失、非普通文件、符号链接或损坏的载荷显式失败。
`reference` 校验身份、围堵、普通文件状态与长度，并返回一个全新的路径提示，不复制/导出字节，
也不做摘要读取。需要完整性校验字节的消费者使用 `load`。私有快照路径永不可能由 StoredFile 表示。
所有公开失败都是领域的 DagError 值。

## 验证（Verification）

聚焦的 Bun 测试覆盖 CAS 与分离的版本一致快照、不可变载荷与配额、重定位、同进程与子进程所有权、
并发死所有者恢复、格式错误的所有权、损坏/未知状态、围堵、释放/在途安全与真实的文件系统失败。
狭窄的仅测试用 rename 拦截在保留真实文件系统操作的同时，安排替换周围的权限失败与一次实际 rename 之后的
完成丢失；不暴露任何生产故障接缝或通用 I/O 框架。以 root 运行时权限测试被跳过。
