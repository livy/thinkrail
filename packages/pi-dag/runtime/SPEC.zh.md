# 运行时（Runtime）

> 中文译文，原文见 [`SPEC.md`](./SPEC.md)。英文原文是唯一权威来源，二者不一致时以原文为准。

## 边界（Boundary）

拥有授权、按 DAG 串行化的转移、持久的意图/效果/观察排序、准入、worker 协议、门禁、干预、
恢复与被动通知。公开接口是 `createDagService`、`DagServiceOptions`。服务拥有执行；
绑定只拥有权限与投递。内部文件是一个模块，不是独立的调度器。外部依赖是公开的 pi、pi-delegation
与 Node API。不导入宿主、UI、subagent 策略或 pi 的私有实现。父 SPEC 声明同级边。

## 状态与效果（State and effects）

一条队列按 DAG 串行化状态变化。只有成功的存储提交才替换其内存快照。一条准备意图在子节点组装之前
冻结输入/配置；实际物化的载荷与不可变的子节点诞生在 `runQueued` 之前提交。一个被保留的 job 把控件
连接到那次调用，永不是未来的某次运行。调度器限制并发组装，并使用 delegation 的运行准入/结算。
它永不启动另一个 provider 循环。

DAG 范围的 interrupt/cancel 只影响拥有已准入尝试的节点；未被触及的 pending 节点保持可恢复，
而对无尝试工作的精确取消被拒绝，转而采用显式 skip。结算观察实际结果、保留精确的历史边界、
在需要时捕获导出证据并评估正向验收。准备失败有单独捕获的证据，而不是伪造的 pi 结果。
超出捕获正文配额的终局评论/错误文本被省略，并附上显式捕获的诊断证据，绝不静默截断；
实际状态、统计与历史边界保持持久。这不会使一份单独捕获的已宣告结果失效。
最新的尝试为其延续保留其狭窄的子句柄；这也保留了在 pi 写入其第一条助手条目之前就被中断的全新会话。
重试、skip 与图编辑，在其失效快照提交之后，为每个受影响的子孙入队保留子节点的退役；
幂等的清理可以在状态队列之外与目标重新组装重叠。恢复忠实重开已保存的诞生；缺失的消息记录永不导致
替换会话。未完成的 job 在状态队列之外完成。如果一次被中断的激活没有已定稿的助手证据，
其冻结载荷被纳入延续：pi 在 preflight 期间可能并未追加原始用户消息。
一个已排队的回答被保留，可选地追加延续指令，而不是静默替换该回答。延续会重新校验已捕获的产物，
并追加其新鲜的路径提示，而不改变其身份/字节，也不重写历史 prompt。这使被重定位的捕获存储仍可用，
而普通文本/JSON 输入仍留在既有的对话中。

worker 协议回执绑定当前助手条目加上 tool-call id；继承来的或更早的 provider id 不是调用身份。
在异步入队之前捕获活跃 job，并在提交之前重新检查那个精确的 job。worker 工具在持久化之前拒绝混合的
助手批次。它们的回调识别真实会话与激活，而不是模型提供的身份。调用回执防止在一次重试的工具调用下
重复捕获已改动的工作区文件。产物路径以非阻塞方式打开，并在读取之前通过描述符检查，
因此特殊文件无法卡住串行化的命令队列。打开之后的 realpath/lstat 检查在读取前后各一次，
要求活跃的、被围堵的路径能识别所打开的描述符，从而拒绝中间目录被替换。两次定位读取，加上前后描述符
身份与纳秒级元数据，拒绝同尺寸的篡改，而不是持久化撕裂的证据。同一个活跃 pi 调用中稍后出现的
唯一批次提案取代其前驱；在协议结果请求终止之后，已排队的 steering/恢复仍可继续 pi。
一个输入门禁不能以此方式被替换：回答它需要配置的权限。大的提交正文与错误细节是文件；
当前快照与历史携带受限的摘要与元数据。历史/通知条目记录准入决策、被拒绝的执行、不确定性、干预与释放，
不携带 provider 凭据，也不带第二套遥测数据库。通知携带受限的目标/门禁/提案身份，以便投递时能重新检查
当前相关性，而不只是附件成员关系。绑定/就绪扫描可以读取已保存的通知而不获取所有权或执行依赖；
活跃提交使用同一个投递谓词。控制器与显式人类会话绑定共享一个附件身份，但不共享权限。
撤销与关闭会移除就绪观察者。

## 读取与恢复（Reads and restoration）

读取不获取执行所有权。它们区分本地所有者、另一个活所有者与无所有者；已保存的活跃工作在没有活所有者时
被投影为 paused/uncertain，直到一次变更声明并持久记录恢复。任何读取都不启动 provider。
重新获取时，不确定的效果永不重发。对账确认静止并解决不确定的干预，同时保留已提交的提案与输入/审批门禁。
它可以建立一个缺失的释放门禁，但永不发明一个成功的结果；人工验收仍然需要一个显式的理由与已满足的门禁。
存储失败会停止本地准入并暴露一个显式错误；它永不发布未提交的候选状态。存在活跃工作或持久清理失败时，
关闭会拒绝成功完成。

## 权限（Authority）

所有者绑定可以管理生命周期，但不能冒充人类。存储的回执先重新校验其自身的权限，再校验其指纹；
成功的重放先于对替换载荷的语义校验/授权以及所有版本/运行时/历史访问。获取会重新检查如今已拥有的快照，
因此一条在被动读取与原所有者死亡之间提交的命令仍会重放，而不是退化成陈旧版本错误；create 在图校验、
执行上下文要求或发布之前也做同样的事。回执保留其原本要求的门禁权限，因此重放永不会针对更晚的图重新施加
一次旧编辑，也不会转移人类权限。仅限人类（human-only）的门禁绑定精确的提案与历史导出。
人工验收记录一次覆盖，而不重写执行成功，也不绕过门禁。重试可以把其自己先前的提案用作修订证据，
而不释放它们。跨节点重试种子需要一个既有的不可变验收决策；这保留了历史授权，
而不把种子当作活的依赖，也不绕过释放门禁。图编辑保留历史证据并使所有受影响的消费者失效；
活跃的失效被拒绝。审批永不修复陈旧的已被消费输入。

## 验证（Verification）

公开客户端测试使用临时存储与确定性的本地 pi provider，覆盖无会话所有者、丢失的 ACK 重放、
冻结的 fork 扇出、门禁权限、控件、分支隔离与恢复。进程内探针与崩溃恢复探针共用一个免凭据的本地
provider 夹具；每个都在创建运行时之前设置其隔离环境。付费 provider 或凭据发现都不是默认的测试要求。
