# 选择工作流

> 中文译文，原文见 [`SKILL.md`](./SKILL.md)。英文原文是唯一权威来源，二者不一致时以原文为准。

工作流家族的根路由器。它对新出现的、符合工作流条件的工作进行分类，并点名管辖它的工作流 skill ——
仅此而已。已经路由的工作则恢复其活动工作流。被路由到的 skill 的步骤只存在于那个 skill 里；
去读它，不要凭记忆执行它。

## 分类（Classify）

对一件新工作，阅读请求并利用已知信息回答三个问题：

1. **这是项目上手吗？** 尚无规格图谱 —— 一个空或实际上为空的工作区，用户带来一个原始想法；
   或者一个既有代码库首次被搭建或首次编写规格。
2. **这是 PR 生命周期吗？** 已完成的工作作为拉取请求交付，或一个既有 PR 正在被照料 ——
   创建、更新到最新、补上截图、照看它的检查，或处理它的评审意见。由某个 PR 自身评审意见引出的修复
   也归在这里。
3. **这项工作改变产品的行为吗？** 一个新特性、一处行为变更或一个缺陷修复 —— 无论多小，即便
   请求已经写明了设计。详细的请求会缩短访谈；它绝不跳过访谈。

如果都不适用，就不需要工作流：直接进行，不宣告工作流。只有不改变行为的工作属于这里：非 PR 的
提问、解释或检查；拼写、仅文档或仅配置的编辑；诸如重命名这类机械式重构。

如果仅凭请求确实无法判断路由，用一个简短的澄清问题（`ask_user_question`，按
**asking-user-questions** 概念 skill 拟定），而不是猜测。

## 路由（Route）

| 分类 | 路由 |
|---|---|
| 项目上手 —— 尚无规格图谱 | 阅读并遵循 **setting-up-a-project** |
| PR 生命周期工作 | 阅读并遵循 **shipping-a-pr** |
| 一个特性、行为变更或缺陷修复 | 阅读并遵循 **brainstorming** |
| 以上都不是 | 无匹配工作流；直接进行，不宣告路由结果 |

一件工作只有一条路由。如果某个请求把未完成的实现与 PR 工作捆在一起，先路由实现，等它落地之后再
回到 **shipping-a-pr**。

## 红旗 —— Red flags — stop and re-route

- 你没有经过 **brainstorming** 就开始实现一个特性、行为变更或缺陷修复。
- “这很小”或“请求已经很具体” —— 两者都不是跳过的理由；工作流会缩小，但不会关掉。
- 你为不改变行为的工作加载了 **brainstorming**（一次重命名、一个拼写错误、一个提问）。
- 你在继续已经分配给某个工作流的工作时又进入了这个路由器。
- 你凭记忆遵循某个已路由 skill 的步骤，而不是去读那个 skill。

## 交接（Handoff）

本 skill 以恰好点名下列之一结尾：**setting-up-a-project**、**shipping-a-pr**、**brainstorming**，
或 **无匹配工作流**（直接进行）。给家族新增一个工作流，就是给上表新增一行 —— 见
**writing-workflow-skills** skill。
