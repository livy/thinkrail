# changes —— 宿主拥有的 hunk/文件回退，带撤销回执

> 中文译文，原文见 [`SPEC.md`](./SPEC.md)。英文原文是唯一权威来源，二者不一致时以原文为准。

## 职责（Responsibility）

评审表面的写路径：**回退工作区中一个 hunk 或一个文件的整个变更**，以及撤销该回退。Git 与工作树是
权威 —— 一次变更点名*用户所看到的*（作用域、两侧各一个行区间、两侧各一个 sha-256），本模块则从自己
的读取重新推导该变更。其背后的平台决策是 [[architecture]] 决策 #19；以下规则是本模块自己的。

## 边界（Boundary）

- **拥有：** `revertChange(params)` 与 `undoChange(params)` —— 先 await 加载（作用域解析加上有界的
  历史字节读取），随后是**同步的 校验→写入/占用 趟**，与 `reviews` 模块的快照趟相同；逐工作区的
  **回执环**；下文的整文件语义表。
- **公开接口（barrel）：** `revertChange`、`undoChange`、`RevertChangeParams`、`UndoChangeParams`、
  `forgetWorkspaceChanges`、`retainReceipts`。
- **允许的依赖：** `contracts`（`ChangeReceipt`/`RevertTarget`/`LineSpan`/`GitDiffScope`）、`git`
  （`resolveDiffRange`、有界的 `readBlobBytesAtAsync` + `readPathModeAtAsync`）、`fs`
  （用于包含校验的 `resolveWorktreeFile`，用于身份与文本性的 `classifyBytes`/`hashBytes`/
  `decodeText`）、`persistence`（工作区查找）、`trash`、`@thinkrail/shared/codedError`、Node 的
  `fs`/`crypto`/`path`。
- **禁止：** `host`、`agent`、`reviews`；`fs` 包含路径之外的任何写入；`unlink`。

## 回退意味着什么（What a revert means）

- **作用域只解析一次，经由 `resolveDiffRange`** —— 「这个 diff 是什么」的唯一定义。只有修改侧*就是*
  工作树的区间才可变；`commit` 作用域以 `SCOPE_IMMUTABLE` 被拒绝（它描述的东西在工作树里什么也没有
  对应）。原始侧在该区间的 **`resolvedOriginalOid`** 上读取，而不是它的 ref，因此一次
  加载→校验→写入 趟的两次读取不会跨越一个移动了 `HEAD` 的提交。
- **两侧的 compare-and-swap，在锁内。** `expect.originalHash` 与 `expect.modifiedHash` 必须等于
  *本次*趟所读到的两侧的 sha-256（`null` = 路径缺失，这正是「新增」与「删除」的表达方式）。任一不匹配
  都是 `STALE_VIEW`，且不写入任何东西：agent 不会因为一次变更而暂停，因此 CAS 就是全部保护。一个
  `uncommitted` 作用域的原始侧是 `HEAD`，提交会移动它，因此它与修改侧受到完全一样的检查。
- **hunk 身份与引擎无关。** 一个 `range` 目标两侧都携带行区间，永不带补丁，因为两个客户端 diff 引擎
  切分 hunk 的方式不同。回退把修改侧行 `[start, start+count)` 替换为原始侧行 `[start, start+count)`；
  `count: 0` 点名 `start` 之前的一个插入点，这正是让「删除该变更添加的行」与「恢复它移除的行」在
  两个方向上成为同一操作的原因。区间针对*本次*读取校验（`RANGE_INVALID`），永不被信任。
- **区间回退仅限文本，且永不改变文件的存在性。** 仅字节的一侧，或缺失的工作树文件，是
  `RANGE_INVALID` —— 整文件回退才是针对它们的操作。
- **行模型是 jsdiff 的：** 只有 `\n` 终止一行，其前的 `\r` 仍是该已终止段的一部分，孤立的 `\r` 是
  普通内容。这正是产生客户端 `structuredPatch` 区间的模型，因此同一个区间不可能指向另一条服务端行。
- **行尾与末尾换行遵循这些行来自的那一侧。** 恢复的原始行携带它们自己的 EOL（CRLF 的基点保持 CRLF）；
  一个不再是文件最后一行的行会用文件的支配性行尾重新终止，因此一段拼接进中间的、无终止的基点尾部
  无法把两行粘在一起。拼接前工作树的末尾换行状态被保留，除非**两侧**区间各自到达其尾部；只有这样
  原始侧的状态才胜出，因为那条尾部就是用户所看到的基点。
- **整文件回退，取决于该文件在作用域中的状态**（从两侧读取，不是读一个状态词）：两侧都在 → 写入原始
  字节（字节，因此二进制文件也被覆盖）；**原始侧缺失**（新增或未跟踪）→ 把经 CAS 校验的工作树文件
  重命名到同目录下一个隐藏的占用名，然后把该占用移到操作系统废纸篓；**工作树缺失**（已删除）→ 恢复
  原始字节，创建缺失的父目录。撤销在逆操作移除文件之前使用同一占用机制。重命名发生在同步校验趟内，
  因此之后一次 agent 写入会重建真实路径，无法成为被 await 的废纸篓辅助函数所移除的对象。若废纸篓
  失败，占用只在目标缺失时才被恢复；并发的重建胜出，原占用则作为 `.thinkrail-recovery-<ulid>` 保留在
  旁边，抛出的错误里带有那个绝对恢复路径。`receipt.trashed` 是辅助函数的绝对输入路径，因此该文件以
  其 `.thinkrail-revert-<ulid>` 临时名出现在操作系统废纸篓中。两侧都缺失就不是变更，被拒绝。一个
  *重命名*的文件按其两半回退 —— 新路径进废纸篓，旧路径被恢复 —— 因为每条路径的两侧实际说的就是这个。
- **符号链接与仅模式变更以 `UNSUPPORTED_CHANGE` 被拒绝。** 工作树身份用 `lstat` 读取，原始树模式来自
  `git ls-tree`；任一侧的符号链接都不被跟随。字节相同而模式不同的不是内容回退，被拒绝。整文件恢复
  应用原始 Git 模式（`100755` 映射为可执行权限）；区间则保持工作树模式。
- **写入是原子的**：同目录下的临时文件、应用所选模式，然后 `rename`。写入中途崩溃会留下旧文件或新
  文件，永不是被截断的文件。

## 回执（Receipts）

- 每次变更都以一个 **`ChangeReceipt`** 作答，其 id 同时也是撤销令牌。宿主在内存中保留一个逐工作区的
  环，每条记录持有该路径的**`before` 字节与模式** —— 恢复该路径原先持有的内容*就是*这里每个操作的逆
  操作，因此没有单独的逆向载荷需要保持同步。因此一个进了废纸篓的文件是通过**把它的字节写回**来撤销
  的，而不是伸进废纸篓 —— 没有操作系统可移植地提供后者。
- **环受双重限界**（`retainReceipts`）：每工作区至多 **20 条回执**，且至多 **64 MiB 的持有字节**，
  最旧先逐出，而**最新的回执总被保留**，即使它本身超出字节预算 —— 刚刚显示的 Undo toast 必须可用。
  20 比一个 toast 的 8 秒生命所能堆叠的更多；64 MiB 把一个工作区能在宿主内存中钉住的上限设为
  `/blob` 会服务的最大 blob。`workspace.remove` 调用 `forgetWorkspaceChanges`，因此被移除的工作区不
  钉住任何东西 —— 而由于移除并不在变更锁之后串行化，`record` 自身就拒绝为宿主不再列出的工作区持有
  回执，因此一次在其工作区消失时正等待废纸篓辅助函数的回退，无法复活这个环。`retainReceipts` 作为
  纯策略导出，因此它的界可以在没有 64 MiB 夹具的情况下测试。
- `undoChange` 把当前工作树文件对照客户端的 `expect.modifiedHash` 做 CAS 检查**并且**，当回执的
  `after` 与当前文件都有模式时，还对照回执的 `after.mode` —— 逆操作也会重写模式，而在一个更新的可执行
  位下的相同字节仍是用户没看到的变更；一个在整文件进废纸篓之后被重建的文件没有 `after.mode` 可比较，
  于是在那里只由客户端的哈希决定，一如从前 —— 然后应用逆操作，然后**消耗**该回执并发出一个自身可撤销
  一次的 `undo` 回执 —— 因此重做就是同一操作，而不是第二套机制。一次被拒绝的撤销（`STALE_VIEW`）或
  失败的逆操作会让回执保持可用；每次尝试都重跑 `resolveWorktreeFile`，因此在回退之后引入的符号链接
  无法把逆操作重定向到工作树之外。
- **回执仅存宿主内存**，重启即失：工作树由 git 跟踪，进了废纸篓的文件可从操作系统废纸篓恢复，因此
  持久化它们只会为一个已被这两者兜底的便利新增一种数据目录格式。宿主不再持有的 id —— 被逐出、随其
  工作区被遗忘，或在一个仍可见的 toast 之后因重启而丢失 —— 是 `RECEIPT_UNKNOWN`，永不是静默空操作；
  客户端把它当作信息（重载，「已无法撤销」），而不是失败。
- 回执 id 是由 Node crypto 生成的 ULID；环顺序仍是插入顺序，而不是从令牌重新推导。

## 必须做对（Get right）

- **客户端从不发送内容。** 参数携带作用域、区间与哈希；写出的每个字节都来自本模块自己的读取。这正是
  让一个陈旧标签页无法覆盖 agent 工作的原因，也是期望哈希是强制而非建议性的原因。
- **失败的原始读取永不是缺失。** `git.readBlobBytesAtAsync` 只在 Git 明确的「路径缺失」诊断时返回
  `null`，其他一切失败都抛出，与 `git.diffFile` 一致。这个区分是承重的，因为缺失的原始侧恰恰是让一次
  整文件回退把工作树文件送进废纸篓的输入。
- **串行化是宿主的事**（`withChangeLock`，每工作区一串，与评审锁分离 —— 见
  [[submodule-server-host]]）。本模块假定自己不会为同一工作区被重入；它不假定 agent 空闲。
