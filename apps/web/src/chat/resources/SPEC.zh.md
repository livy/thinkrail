# Chat Resources —— 命令与 subagent 工作以及 MCP 服务器的触发器、停靠区与检查器

> 中文译文，原文见 [`SPEC.md`](./SPEC.md)。英文原文是唯一权威来源，二者不一致时以原文为准。

## 职责（Responsibility）

当前 chat 的 **Resources** 各表面：一个带 MCP **注意力标记**的头部**触发器**、一个位于输入框上方的
环境式**停靠区**，以及一个覆盖在会话记录之上的**检查器**。它们共同让 agent 创建的工作——后台命令与
subagent——在你打字时可一眼扫到、无需滚动到旧工具调用即可检查，并且可以停止，同时不会把它与用户自己的
工作区终端混淆；它们还显示该 chat 的 MCP 服务器及其按 chat 的动作。

三者通过同一套行法（row grammar）渲染同一份宿主上报的快照；没有一个是常驻面板或工作台标签页。检查器
位于 chat 列内部，并让输入框保持可用。同一套行法还拥有会话记录的**结果行**（见下文），因此一个已完成
的命令或后台 subagent 在 chat 中与在 Finished 中读起来一致。

## 边界（Boundary）

- **拥有：** props 驱动的 `ResourcesButton`、`ResourcesAttention`、`ResourcesDock`、`ResourcesInspector`、
  `CommandLogView` 与 `ResultRow`，经 `index.ts` 导出，外加它们共享的私有行/状态词表与私有 MCP 行
  （`mcpRow.tsx`）。检查器渲染名单与细节*头部*；细节*主体*是由父级填充的槽，结果行的展开主体也是如此。
- **公开接口：** `ResourcesButton`、`ResourcesAttention`、`ResourcesDock`、`ResourcesInspector`、
  `CommandLogView`、`ResultRow`、`ResultReceipt`、`ResultSource`、`ResourceTarget`、`newestResourceId`。
- **允许的外部依赖：** contracts、React、Remix 图标、共享 UI 基础组件与主题工具类、`@thinkrail/locales`
  （UI 字符串），以及 `lib`（共享的 MCP 状态词表）。时间作为 `now` prop 传入，使格式化保持纯粹。
- **禁止：** store/传输层、server/portable 扩展包、Pi 值导入、进程执行、日志持久化、subagent 会话记录
  抓取，以及工作台放置。父 chat 的集成（谁填充细节槽、这些表面挂在哪里）与兄弟依赖边属于
  [[submodule-web-chat]]。

## 行法（Row grammar）

每个表面都把一份资源渲染为一行：种类 glyph 加状态点 · 名称（命令显示名或 subagent 角色）· 活动
（命令文本或任务）· 状态 · 已耗时，悬停与聚焦时以 Inspect/Stop 取代状态文本出现，因此行的高度绝不变化。
行的视觉状态把线上状态收敛成一种在途呈现与四种已结算呈现：

- *运行中*的命令与*运行中*的 subagent → **Working**（主色，呼吸点）；*排队中* → **Queued**；
  *正在停止* → **Stopping…**——全都在途、全都排在已结算行之前，**不管实时状态如何都按开始时间最旧
  优先**，因此行在其开始或开始停止时绝不跳动；
- 退出码 0 的*已完成* / *已完成的* subagent → **Done**（成功）；非零退出、*错误* → **Failed**
  （错误色，自动可见）；*已停止* / *已中止* → **Stopped**（中性：用户停止不是失败）；任何被标记
  `interrupted` 的运行 → **Interrupted**（中性，电源 glyph），无论它携带什么状态——是宿主或 chat 的
  拆除切断了它，既不是用户的停止，也不是工作的失败。

状态始终是 glyph + 颜色 + 词；颜色与动效绝不是唯一信号。已耗时是粗粒度的（分钟），因为共享时钟每 30 s
才走动一次；它是实时行的时长，或已结算行的运行时间——命令的完成减开始，subagent 的宿主上报
`durationMs`（较旧宿主缺失，因此该行不显示时长，而不是给出猜测）。退出码渲染为等宽徽标。

## 呈现（Presentation）

**触发器（Trigger）。** 头部按钮读作 **Resources** 加上仅在快照权威时才显示的活动资源计数：实时行加上
已连接或正在启动的 MCP 服务器，然后是为父级报告用户尚未看过的已完成结果准备的 "N new" 药丸（也在其
可访问名称中）。图标只在后台工作运行（`working`）时呼吸，因此一个始终连接的服务器绝不会让头部动画。
在首次读取之前、重连期间，或刷新失败之后，它显示显式的不可用计数标记与匹配的可访问标签，而不是宣称
零。父级空闲不隐藏其资源。窄宽度下标签可以折叠，但控件/计数状态与可访问名称仍可用。触发器切换检查器
并携带 `aria-expanded`。只要该 chat 的任一服务器需要登录、失败或等待批准，就会出现一个独立的小
**注意力标记**（`ResourcesAttention`，一个兄弟按钮，绝不嵌套），它打开 Settings › MCP servers。

**停靠区（Dock）。** 停靠区用于在途工作：它把实时行直接列在输入框上方，绝不列已完成的（用户结算，
2026-10：已完成工作只存在于 Resources）。行下方是一行安静的摘要——`✓ N finished · M new · Open
Resources`——汇总该 chat 的每条已完成记录（父级的 `finishedCount`）与父级标记为**新**的结果
（`freshCount`）；整行是一个控件，请求父级打开检查器（`onOpenFinished`；父级把它落在最新的新结果上，
否则落在最新的已完成上，两者都由 contracts 历史顺序中的纯函数 `newestResourceId` 挑选）。只要该 chat
有任何已完成记录它就保留，包括什么都没运行时，而当既无在途也无已完成工作时停靠区什么都不渲染。超过
四行实时行时，它们折在同一行的 `N active` 切换（带逐种类实时计数）之后；折叠/展开的选择是停靠区本地的。
重连期间，摘要行会在活动计数旁说明这一点。停靠区的一行恰好有两个控件：其名称与活动合起来是一个 Inspect
控件，在检查器中打开该行；Stop 请求取消该行。停靠区在检查器打开时**隐藏**，因此实时名单绝不渲染两次。
它为行预留空间，而不是在每次变化时动画改变高度，因此输入框不会抖动。

**检查器（Inspector）。** 一个非模态、就地的对话框，覆盖会话记录区域，同时 chat 头部与输入框仍可见可用：
一列名单加一列所选行的细节。名单按种类对工作分组——先是 **Commands**，然后 **Subagents**，各自带其
实时与已完成计数作头部，且在其两者皆无时省略；当该 chat 从未运行过任何东西时，由一行空文案顶替——
然后是 MCP 服务器。一个种类内部先放其实时行，然后 **Finished · N**（N 是来自父级 `history` 统计的该
chat 全部历史，而不只是它持有的行）。最新的五行已完成行位于一个**折叠行**之上，即 `› K more finished`
加上被隐藏部分的结果统计（✓ done · ✕ failed · ◦ stopped or interrupted，也在其可访问名称中）。折叠
状态下，该折叠还保留每条**新**结果（`newIds`，以可见的 `new` 标记与可访问名称中的 `, new` 高亮）与
它所选中的行，因此新结果绝不会被隐藏，而从别处打开的行也在视野内。展开会在折叠行下方按历史顺序揭示
其余部分，并只保留最新五行在其上方，因此穿行列表绝不重排它；展开的尾部以 **Show 20 more · L left**
（当宿主比父级持有更多时——`remaining`、`onLoadMore`；较旧宿主缺失）与 **Collapse** 结束。展开状态是
父级的按种类状态（`expanded` / `onExpandedChange`）；一次分页加载的待定与错误状态作为
`history:<kind>` 动作到达。折叠之下未显示的行不是可选项，因此 `↑`/`↓` 只走可见的东西。页脚说明历史
住在哪里：保留到工作区被归档（`retained`），或对较旧宿主只保留本宿主会话期间。细节头部重复该行的名称
与状态，并为实时行提供 Stop、为被中断的运行提供一行原因，另外——对快照携带 `model` 的 subagent——一个
由父级的 `renderSubagentModel(summary)` 渲染的 **Model** 项（宿主未发送模型时则无）。名单与停靠区的行
刻意省略模型：它会挤掉任务，而任务才是区分两次运行的东西。细节主体是父级的槽——命令用有界的纯文本
命令输出（本模块的 `CommandLogView`），subagent 用只读的 subagent 会话记录面板。名单是一个 listbox：
点击即选中，`↑`/`↓` 移动选择，`Esc` 或关闭控件忽略，而点击输入框或头部**不会**忽略。每个选项把其活动
保留在第二行以及其可访问名称中（`name: activity, state`），因此两个同角色 subagent 仍可区分；选项内部
不含控件——其 Stop 是展示型行包装层内的一个兄弟，该包装层携带该行的 test id 与 `data-selected`。
**Stop all subagents** 位于名单头部，由父级点名当前活动计数的确认守护；它绝不停止主 chat，也不禁用
未来的委派。过期/不可用的快照显示一条横幅并禁用控件；读取失败保持可见并带 Retry。

**MCP 服务器（MCP servers）。** 当快照携带 `mcpServers`（宿主处于 `MCP_PROTOCOL_VERSION`；`null` 则
隐藏该列表）时，名单在 Finished 之后增加第三段。这些行不是 listbox 选项，也绝不出现在停靠区——服务器
不是工作：插头 glyph 加状态点 · 名称 · 共享状态标签（已连接时带工具计数）· 传输层（stdio 为
"runs on host"），注意力行在前。动作随状态而变：**Disable in this chat** / **Enable in this chat**
（在该 chat 下一次空闲重载时应用，这会重启它的其他服务器——列表下方一行辅助说明如此；绝不在
`registered` 行上提供，即扩展注册的服务器，宿主拒绝对其按 chat 禁用）、**Reconnect** 用于失败或已断开，
以及 Sign in / Review / Edit 用于需要登录、待批准或配置无效的情形，它们打开 Settings
（`resource-mcp-settings`），与该段头部的 **Settings** 按钮（`resources-mcp-settings`、
`Button soft-primary s`）相同。没有 PID，也没有立即停止：pi 两者都不提供。没有权威时控件被禁用，每个
服务器同时只有一个请求在途，错误留在该行上。

**回执（Receipts）。** 会话记录的轮次分隔线可以携带父级提供的 "N still running" 徽标块；它打开检查器，
并且是唯一的 chat 体内名单提示——没有内联列表。

**结果行（Result row）。** `ResultRow` 为会话记录渲染一条历史完成通知（`background-command-completion`
或 `subagent-completion` 消息的细节，或 agent 拉取到的某个已完成结果的细节）：chevron · 带状态点的种类
glyph · 可选的 `receipt` 引导（"Agent received" / "Agent replies after your next message"）·
`Background` / `Subagent` · 名称 · 状态 · 运行时间（与 Finished 行显示的同一个粗粒度
`formatElapsed`）· 退出徽标（命令）· 可选的父级提供 `metaLead` 节点（subagent 的模型标签）与 `meta`
文本 · 一行摘要 · 可选打开动作（"Open log" / "Transcript"）。命令摘要是摘录中最后一行非空内容，且已移除
ANSI CSI 序列；subagent 摘要来自父级，因为报告文本由它拥有。摘要在展开期间隐藏，在窄宽度下最先让位，
并对命令输出保留代码字体。该行是**受控的**：`expanded`、`onToggle` 与 `toggleRef` 来自父级的会话记录
折叠状态，而没有 `onToggle` 就无可展开。它绝不宣称当前权威——打开动作是否存在由父级根据自己的快照决定。
其状态点外环按会话记录画布绘制，而不是按抬高的名单表面。

命令输出是纯等宽文本，不是交互式终端，也不是被解释的标记。当只剩有界尾部时说明这一点，并区分空输出、
加载中、瞬时读取失败与永久不可用的输出——以及为何不可用：一条被中断、其宿主在能保留日志之前就死掉的命令
会如此说明；对保留日志的宿主（`retained`），其他任何情况就是简单地缺失；而对较旧宿主，它是随宿主的运行时
历史一起被驱逐的。

成功的 Stop 意味着请求了取消，而不是可以伪造一个终态。当控件请求待定时，避免重复提交；后续状态来自宿主。
一个已完成的资源与一次点击竞速是无害的。过期/断开的视图在获得当前权威之前无法提供活动控件，而与旧宿主的
连接会隐藏触发器、停靠区与检查器，而不是显示一个空列表来证明没有东西在运行。

关闭检查器、停靠区或 chat 放置位置绝不停止工作。检查器关闭时，键盘焦点回到头部触发器；若已知的较旧宿主
移除了该触发器，焦点则回到输入框。一次"从受支持到已知不受支持"的 welcome 会退役检查器与 Stop-all 确认。
一次协议支持未知的瞬时重连会把已打开的检查器保留为过期状态，而不是错误地归类宿主。使用既有的 Radix 基础
组件（就地 `DialogPanel`）、仅 token 样式，并在状态图标旁配上可见文本。

subagent 列表包含本 chat 的直接前台与后台子会话。后台运行的摘要会说 `detached`（子会话的 `info`，绝不
从 queued/running 猜测），而只有这些——加上已完成的命令——可以是新结果：前台子会话的报告已在其自己的
卡片中到达 agent。本版本没有递归树、工作区/全局作用域、重启/steer 动作、产物、需要你（needs-you）状态
（子会话无头运行），也没有任意 shell 进程发现。普通工作区终端标签页不会出现。

## 验证义务（Verification obligations）

覆盖 空/活跃/已完成/过期/不可用 各状态、确切的实时计数、停靠区的仅实时行、其已完成摘要行（总额、新计数、
落点）与其折叠规则和"检查期间隐藏"规则、检查器按种类分组、其折叠（最新五行、钉住的新行与选中行、隐藏
统计、展开后的顺序、带剩余量的分页、较旧宿主的缺席）、Interrupted 状态与其日志消息、触发器"只在工作时
呼吸"与未知计数标记、MCP 段的逐状态动作、对较旧宿主的缺席与注意力标记、键盘导航与焦点返回、安全的纯文本
日志、逐行的停止失败与 stop-all 确认、subagent 细节的模型项（无模型时缺席），以及结果行的状态映射、摘要
派生、受控展开与可选打开动作。浏览器覆盖必须证明当前 chat 的隔离、重载/重连的水合、检查器关闭期间的
迟到完成，以及视图关闭不会造成取消。
