# shell/layout —— 前端本地的工作台帧

> 中文译文，原文见 [`SPEC.md`](./SPEC.md)。英文原文是唯一权威来源，二者不一致时以原文为准。

## 职责（Responsibility）

shell 拥有的无头工作台引擎：归一化的前端本地帧与按工作区视图语法；合法的原子变更与投影；递
归中心加左/右/底渲染；尺寸/对齐与拖动几何；键盘排布命令；以及焦点恢复。它渲染容器；功能视
图保持与排布无关。

## 边界（Boundary）

- **拥有：** web 本地的 `WorkbenchFrame`/`WorkspaceViewState` 类型；帧加视图的投影；纯粹的
  拓扑、放置、注意与策略操作；语义最小值与独立组上限检查；单结果拖动预览；中心/侧/底渲染器；
  由对齐拥有的嵌套组合与侧宽投影；标签条溢出；ARIA 标签页/分隔条行为；以及终端可见性门禁。
- **公开接口（`index.ts`）：** 所有当前布局类型；工作台渲染器/控制器；边缘 chrome 原语
  （`AuxiliaryRail`、`AuxiliaryRailToolButton`、`AuxiliaryPaneHeader`、
  `AuxiliaryPaneHideButton`）；纯变更、投影与校验辅助函数；内置预置定义外加实例化/应用/捕
  获操作与 `frameMatchesPreset`（忽略生成 id 的几何相等性，Settings 用它标记已应用的预置）；
  注意回退辅助函数；以及不可用原因结果。调用方注入资源渲染器并提交完整的纯结果，而不是拼
  接数组。
- **外部依赖：** `@thinkrail/contracts`，仅用于无资源的自定义预置 DTO 与 git diff-scope 类
  型；shell 中立的 `lib` 注意/id 原语；React；`@thinkrail/ui/*`（含
  `@thinkrail/ui/resizable`）；`@dnd-kit/core`。
- **禁止：** server/shared/pi 导入；领域资源寿命；浏览器持久化或 WS 调用；功能面板内部；可
  变的第三方停靠模型；内联组件样式；或非语义的颜色值。

## 状态契约（State contract）

一个 `WorkbenchFrame` 属于某个前端表面，而不是某个工作区。它携带稳定的组/分割 id、中心拓扑、
左/右/底组与几何、辅助可见性/折叠、底部对齐、单例工具放置/顺序，以及恢复目标。它不携带任
何工作区资源身份、预览、选中标签页、导航时钟、指针草稿或视口压缩。

一个 `WorkspaceViewState` 按工作区做 key，并引用帧组 id。它携带文件/diff/变更/chat/文档/终
端的成员关系与顺序，外加中心预览身份（`changes` 标签页是 store 规格里定义的按 scope 评审表
面；它的布局记录是 kind + id + name + scope，不缓存任何东西，并且与文件、diff 标签页一样有
资格成为预览）。独立的 `LayoutAttention` 覆盖层携带每个组的选择、中心与各辅助区域的最后焦点，
以及按组的导航时钟。注意按工作区做 key，但选中的单例工具在整个窗口的视图中共享（资源选择
则不然）；纯粹的采纳规则在这里，它的扇出在 `layoutState`。挂载的工作台文档是那唯一的帧、活
动工作区视图及其注意的纯投影；它绝不作为另一个权威被存储。

纯操作要么返回一个完整的本地状态结果，要么返回一个不可用原因。仅资源的命令修补活动工作区视
图。帧命令返回帧外加每一处必需的保留工作区重映射；store 通过
[[submodule-web-shell-layout-state]] 原子装入该结果。组件从不拼接组或标签页。稳定 id 是放
置键；标签页的 `name` 仍是非身份元数据。单例工具名在呈现时从当前 web 拥有的目录解析，因此
文案更新绝不会重写本地布局状态。不可用原因是操作运行时才解析的本地化文案，从不持久化。在渲
染期间求值的辅助函数（`layoutTabName`、`describeLayoutGroup`、`removeLayoutGroup`、
`separatePanesReason`、`layoutPresetName`）把调用方的翻译器作为第一个参数，因此语言变化会
重算它们。`layoutTabName` 在渲染时按标签页的种类（工具、未命名 chat、默认终端、Changes
/diff scope、计划文档）经 `lib` 的默认名辅助函数为每个默认名定措辞，而用户或 agent 设置的
名字则逐字显示。它的可选第三个参数，即 Workbench 的 **`chatFirstPrompts`** prop
（`ChatFirstPrompts`，按会话 id 的首提示，由 shell 在 `onRenameChat` 旁注入），通过 `lib` 的
`chatDisplayName` 用 chat 的首提示为未命名的 chat 标签页 —— 以及存储的 chat 名为空的计划文
档（按 `sourceId`）—— 贴标签，用在条带、其溢出搜索、拖动覆盖层与移动目标摘要
（`describeLayoutGroup`、`tabSearchKeywords`）展示该名字的每一处；chat 标签页渲染同一个
`chatLabel` 以提供 `data-title-source` 与完整提示 tooltip，而重命名字段仍然编辑真实的
`name`。该标签只是呈现：文档的 `name` 保持为 `""`，因此 Workbench 基于所拿到文档提交的每一
次变更都会让该 chat 保持未命名。

对文件、spec 或 diff 浏览行的点击会立即打开其预览，没有结算等待。双击则就地提升同一处放置。
在读取仍在途中到达的 keep 会合并成一次携带前导预览槽位声明的最终 keep。只有两条打开路径
等待共享的 250 ms 结算窗口：对活动预览标签页的单击（或键盘激活），这样双击不会被读作两次
keep；以及 Changes 评审标签页的预览，即使是由代码而非点击打开，它也会等待。在打开路径之外，
遗留选择的 Review 揭示会等完某个浏览行窗口剩余的时间。`isToolShowing` 与
`showingAuxiliaryKey` 读取在展开的 pane 中选中的是哪些辅助工具，因此 shell 能判断 Review
是否显示、以及用户此后是否换了工具。指针/尺寸草稿与视口压缩仍只存在于运行时。

帧组在任何工作区里都可以保持为空。因此关闭最后一个资源不会动拓扑。显式的移除/合并是删除组
的唯一方式，它的结果会把引用该组的每个资源在本地保留的所有工作区视图里重新安家。始终至少保
留一个中心叶子。

## 辅助呈现与召回（Auxiliary presentation and recall）

边缘条目是当前文档与注意的派生投影，绝不是第二份被持久化的布局。**工具栏镜像区域的
pane**：条目按有序簇给出，文档顺序下每个组一簇，簇间以细线分隔，因此工具栏无需标签条就能回
答 "哪些图标共用一个 pane" ——组模型仍是权威，只是变得可观察。单例条目落在持有它的那个组的
簇里；每个承载终端的组有一个条目，带自己具名的会话标签页；空组是一个单条目簇。无处放置的工
具（在执行 *Remove tool from group* 之后）形成一个尾随的、变暗的簇，位于最后一个分隔符之后；
激活其中之一会把它恢复到记录的目标。每个展开的 pane 恰好有一个条目处于按下态，折叠或隐藏
的 pane 中没有，因此按下集合读起来就是 "当前打开的 pane"。点击未按下的条目会在*它自己的*
pane 里选中它（揭示或展开该 pane）；点击已按下的条目则折叠该 pane。

**工具与终端绝不共用一个 pane。** 持有工具的组是工具 pane；终端只存在于无工具的组里
（`canJoinAuxiliaryGroup`）。把一个工具加入显示终端的 pane，或把一个终端加入工具 pane，都是
不可用的（"Tools and terminals use separate panes."）；新建一个 pane 总是可以的，而移除一
个 pane 会把它的标签页合并进最近的兄弟（先前一个，再下一个）中能全部接收它们的那个，否则保
持不可用。归一化把同一规则应用到保留的工作区视图：一个其所在组变成工具 pane 的终端，会重新
安家到同一区域最近的空闲工具 pane，然后是空闲工具的底部 pane，然后才是中心。被动的终端放置
与预置重映射用该谓词选择目的地。这条规则之所以存在，是因为混合 pane 没有连贯的渲染方式：一
个选中终端的 pane 是一条会话标签条，其中的兄弟工具在任何地方都不出现。有了这条规则，先前的
混合顺序锚点（`beforeToolByTabId`）与终端条带的文档索引管道都消失了；仍旧携带该字段的持久
化视图会被接受，并丢弃该字段。

终端条目恢复该 pane 选中的会话，否则恢复它的第一个终端；因为终端 pane 除了终端什么都不放，
`selectedByGroup` 就是完整的召回，先前的 `lastTerminalByGroup` 字段已消失（保存的副本会被
忽略）。资源选择从不参与单例工具的扇出。激活已显示的条目只折叠它所在的组；恢复条目则在一次
转换中完成揭示/展开/选中。空的底部条目揭示的是无进程的创建表面，而不是终端预留。

`AuxiliaryRail` 是一个由 props 驱动的工具栏，只拥有 roving DOM 焦点。工作台通过既有的
`WorkbenchTab` 菜单/拖动控制器来适配已放置的工具；终端组条目是导航而非拖动或关闭某个代表会
话。选中的工具会得到一个朴素 pane 头部，其标题是该工具的拖动把手 —— 与它的工具栏条目相同的
拖动数据，因此看着 pane 而不是边缘的用户仍能找到可抓之处；选中的终端保留具名的会话标签页。
Project Home 组合该头部但不带拖动数据。工具栏、它的工具条目几何与选择类、朴素 pane 头部及
其 Hide 控件，是边缘 chrome 样式的唯一所有者：`WorkbenchTab`（工具栏模式）与可放置的
`AuxiliaryRailButton` 复用条目的框架/按钮类辅助函数，`AuxiliaryGroupHeader` 复用头部组件，
而 shell 的 Project Home 分支（[[submodule-web-shell]]）把导出的 `AuxiliaryRail` /
`AuxiliaryRailToolButton` / `AuxiliaryPaneHeader` 围绕自己的几何组合起来，因此无论有没有帧，
工具看起来都一样。每个工具栏条目都是一个 `data-active` 的 32px 框架（底部工具栏中为 24px），
包着一个套用共享 `ghost` M 图标按钮皮肤的控件（`buttonVariants`，[[module-ui]] 的
"Button system"：24px 方块、16px 图标、共享悬停 —— 按下时外观相同 —— 以及画在方块内部的
ghost 纯图标焦点环，因此工具栏的边距或条带边缘不会裁掉它）。该控件为自己的元素保留 roving
工具栏、拖放与装饰；打开态条目设置 `data-selected`（共享的 `control-bg-selected` 填充），而
放置提示位于控件上 —— 被动放置提示加上内嵌的 `primary-soft` 圆环，因此它在填充占据背景的已
选中条目上仍然可见。装饰（评审徽标、终端序号）偏移到 32px 框架的角上，而 join 可放置目标就
是框架本身，因此两者都不会随 24px 控件缩小。标签页与工具图标在一处解析（`tabIcon`），静止
时为 Line，激活时为 Fill；工具栏 tooltip 朝远离自己边缘的方向打开。工具栏几何被排除在可用
pane 空间之外，但保存的尺寸仍是工作台范围的比值；视口投影绝不重写它们。测量观察者跟随实际
DOM 节点走过 ref 的附加/清理，包括被 key 的面板组替换；挂载的工作台并不意味它所测量的后代
仍然存活。工具栏选择是选中填充加 Fill 图标（以及 `aria-pressed`）—— 没有强调边缘：工具栏是
一列图标按钮而不是标签条，因此它没有下划线的对应物。它在每个主题下都相同 —— 调色板决定它读
起来多响，绝不是组件里的按主题选择器。

## 布局语法（Layout grammar）

- **中心：** 递归的水平/垂直二叉树，最多四个叶子。一次分割用一个等分的两半替换一个叶子。用
  户创建/调整尺寸要求每个子项至少保持 320 px 宽、180 px 高。空叶子是合法的帧槽位，渲染
  shell 提供的空表面。移除/合并提升一个兄弟，并确定性地为每个受影响工作区的标签页重新安家。
- **辅助资格：** Projects、Specs、Files 与 Review 是帧拥有的、仅限辅助区域的单例工具；终端
  是工作区资源，可以占据中心或任何辅助区域。隐藏单例会保留它的恢复目标。视图/深链揭示会在
  帧本地位置恢复或展开它，并在当前工作区注意中聚焦所请求的项。
- **左/右：** 常驻全高工具栏旁的有序垂直帧堆栈。把外层分隔条拖过它的最小值会隐藏该侧并保留
  最后展开的宽度。上下两半的宽泛主体目标会创建相邻组；工具栏的簇边界区域为折叠或隐藏的
  pane 提供同样的命令。展开的主体有 120 px 的常规最小值；折叠的组不占据内部主体空间，并保
  留其展开权重，在边缘栏上恢复。空的帧组在各工作区之间保持可用，直到显式移除，并渲染一个具
  名的 Add/Reveal 表面而不是消失；含有组的区域可以保持隐藏。
- **底部：** 有序的、从左到右的帧组在垂直分隔条上调整尺寸。折叠的组只保留其边缘栏控件，没
  有内部垂直条。常驻的底部工具栏覆盖由底部对齐选中的那一列，即使主体被隐藏或没有组。一次底
  部合格的拖动会在未使用的工具栏空间里暴露一个宽泛的 Primary 恢复/放置目标，同时让显式的组
  控件仍可触达；放置会揭示它的目的地。没有拖动活动时，`Mod+Shift+J` 与工具栏提供同样的恢复
  路径。高度从 30% 开始，主体最小 120 px，上限 70%。对齐是 center、center+left、
  center+right 或 full workbench。被排除在该跨度之外的侧边拥有它的下角并延续到工作台底部；
  被包含的侧边结束在其上方；拖动时的放置区遵循同样的归属。对齐在尺寸调整与窄幅压缩期间跟随
  实际的浏览器本地侧投影，而持久化的工作台范围帧比值仍是目标，并通过嵌套面板组换算。分隔条
  手势只提交它拥有的那侧的比值；未被触碰的邻居的压缩仍只存在于运行时。隐藏的侧边不贡献幻影
  宽度。可见的空底部帧槽位在各工作区之间保持可用，直到显式移除，并渲染终端创建/揭示提示。
- **上限：** 左/右共享一个本地设置，默认每侧六个组；底部有一个独立的本地设置，默认三个。两
  者都接受 1–32，带有封闭的硬安全界限，即使对不可信的本地状态或共享预置也会强制。已存在的
  超限会保留；创建在低于配置上限之前不可用，而重排/合并/减少移动仍然合法。稳定 id 唯一性、
  每个工作区视图一个规范资源放置、归一化几何，以及最终中心叶子不变量，由每一次变更强制。
- **小视口：** 恢复到更少空间时，本地可以压缩到低于操作最小值。内容滚动/裁切；底部对齐从实
  际压缩后的侧跨度投影，而帧拓扑、对齐选择与比值绝不会仅因为这个视口很窄就被重写。

普通打开会指向活动工作区最后聚焦的存活中心组。重新打开一个规范资源会选中它已有的本地放置而
不是复制，并就地刷新非身份元数据。每个中心组有一个工作区本地的预览槽位：预览就地替换，keep
单向提升，导航时钟是组本地的。被动恢复可以选中它的第一个结果而不推进用户导航时钟。用户打开
在请求时推进它的时钟，并把这个戳记一路带到接受，而不是计两次；重选活动中心标签页也推进一次，
这样它能压过更旧的延后工作。附带的 DOM 焦点变化会更新最后焦点路由，但不推进导航。

异步完成从被移除的组改路由到当前最后焦点，并把存活的目的一次推进，除非更新的本地放置已包含
该资源。文件/chat/文档的关闭立即更新本地注意。终端关闭等待宿主域接受，然后从该工作区的每个
本地工作区视图中移除该终端；被拒绝则放置与注意都不动。任何更新的标签页手势或导航都会抑制延
后的关闭焦点恢复。

## 不重挂载的形状变更（Shape changes without remounts）

引擎渲染的每个 `ResizablePanelGroup`（外层列、对齐行、底部列、侧与底堆栈、中心分割）只有结
构性 key；投影 epoch、侧可见性、底可见性、折叠与对齐绝不做组的 key。出现或消失的区域就地增
删它的 `ResizablePanel`，带稳定的 `id` 与 `order`，而底部列是一个始终挂载的垂直组，其底面板
是有条件的，因此顶行永不换父级。因此当相邻 pane 折叠、隐藏或显示时，资源体、工具 pane、终
端与 chat 转录保留各自的 DOM 与组件状态；唯一的重挂载是在外层列与对齐行之间迁移的侧堆栈，
因为底部对齐或角落归属发生了变化。

尺寸不交给库的重新分配。`defaultSize` prop 总是携带当前面板集已提交的投影，因此成员变化会
重新计算到已提交的几何上，而每组的 layout effect 会在差异超过容差且组的 panel 数与提交值匹
配时，用 `setLayout` 重新应用已提交的尺寸。依赖面板集的那些最小值（`minSize` 由存在多少个组
或侧边推导而来）在组会员关系变化的那一次提交里被放宽为 `0`，并在同步的后续提交中应用
（`useTopologySettled`）：react-resizable-panels 会在该 panel 的 layout effect 中，针对组尚
未重算的布局重新求值该 panel 的约束，让某个约束与兄弟 panel 在同一次提交里一起变化，会使它
索引到过期布局并抛异常。强制生效的 effect 以那个已结算标志为 key，因此一旦真实约束生效，已
提交的尺寸就会被重新应用一次。手势的回滚（`restore`）同样拒绝写入长度与组已不匹配的布局。

## 排布与无障碍（Arrangement and accessibility）

一次标签页拖动只绘制一个结果：条带插入、整组 join、合法的中心半分割、侧上/下边界，或底部的
左/右边界。展开的终端条带仍是 join/重排目标，同时主体可以创建相邻组。在工具栏上，两种目标
遵循簇语法：条目的前后两半插入*那个 pane*（重排，或从任意位置 join），而每个簇边界 —— 工具
栏起点、簇之间、工具栏末尾 ——都带一个 **New pane here** 区域，在该索引处创建组，取代原先紧
凑的折叠/隐藏侧创建细条。两种目标都只在合法时绘制：边界区域需要在本地上限下还有余量，且必
须不是精确位置上的 no-op，join 目标则遵守工具/终端 pane 规则。隐藏的侧工具栏在本地上限内保
持一个宽泛的空闲空间创建目标。底部未渲染时，它拖动时的区域复用活动工作区最后聚焦的存活底部
帧组，回退到尾部组，或只在没有任何组且本地底部上限允许时才在尾部边界创建一个；任一放置都会
揭示该区域。成功的显式辅助组/插入放置也会在同一次交互变更中展开它们的目的地；通用放置与被
动的终端对账保留它们不展开的策略。非法域、上限、精确位置上的 no-op 与最小值违规都不绘制目
标也不提交任何东西。Escape、指针取消、外部放置，或一次取代性的本地帧/视图转换会恢复源。一
次拖动移动一个工作区资源或一个帧拥有的工具；它绝不复制，也不跨工作区。

放置目标样式没有静止态。一旦某个可移动标签页被拿起，每个当前合法的目的地都会显示一个微妙的
Primary 提示，指针下的目的地会加强。两种状态都派生自既有的拖动状态与各站点已算好的合法性
—— 没有第二个拖动状态机 —— 且只使用语义化 Primary 角色，绝不用 `feedback-*`：`drop-hint`
是微妙的 Primary 轮廓或半透明表面，`drop-active` 更强。标签页头部目标会为整个组头部描边；
单个前/后插入标记仍是精确的悬停提示。中心分割目标在拖动开始时显示紧凑的方向性边缘提示，并
在悬停时填出真正会得到的那一半。底部拖动时区域高 24 px，并在该带内对重叠的下部主体目标取得
碰撞优先。活动强调在指针离开时清除；所有提示在放置或取消时清除；装饰层绝不改变命中测试或已
提交的结果。

创建或删除组显然是帧命令，因此影响这个窗口里的每个工作区。在已有组之间移动资源只影响它所在
的工作区视图。移动单例工具在这个窗口内全局改变帧放置。未提交的拖动/尺寸草稿留在运行时本地，
在放置/指针抬起时提交一次；任何宿主修订版都无法取消它们。本地投影 epoch 与必需的工作区身
份，在不重挂载工作台的前提下栅栏住手势与延后的焦点/预览结算工作。即使新视图里也存在同一个
单例放置或确定性终端 id，一次工作区切换也会取消进行中的手势；过期的焦点请求在返回时不会被
重放。被标记 `onlyIfFocusLost` 的焦点请求只在 DOM 焦点缺失、位于 `body`、已断开或不再渲染时
运行；该检查在请求执行时进行，也就是排布提交之后。`hideSide`/`hideBottom` 把它们的中心焦点
目标标记为 `focusOnlyIfLost`，而应用它们的每条路径都遵守这一点：全局快捷键、头部与菜单隐藏，
以及把分隔条拖到零来折叠区域。标签页移除也会取消它的拖动。使调整尺寸失效会在绘制前恢复实
时面板组已提交的投影，并在此次手势释放之前拒绝其余部分，而不仅仅是它的待持久化写入。同样的
恢复适用于外层/对齐的侧边、底部高度、辅助堆栈与递归中心分割，且不以工作区做工作台的 key。
被取消拖动的播报只保留给在其基础或工作区被替换时仍在进行中的指针/键盘手势，或给某个标签页
已离开文档的标签页拖动：`@thinkrail/ui/resizable` 会在每次组挂载与常规调整尺寸时汇报布局，
因此仅仅是经历过先前本地转换的组不会播报任何东西。

指针绝不是唯一的排布路径。键盘控件与 shadcn 菜单覆盖组/标签页焦点、选中/关闭/keep/重排/移
动、方向性中心分割、绝对与相邻的辅助组创建、显式的组移除/合并、折叠/显示/隐藏/工具恢复、底
部对齐，以及键盘分隔条调整尺寸，并总是附带不可用原因。一个标签页可以通过移动加 New group
复现每一处内部的指针放置。可选的 chat 重命名菜单项把标签页标签替换为内联编辑器，并通过
shell 注入的回调提交：布局识别出 chat 标签页并拥有这段瞬态编辑交互，但绝不导入
transport/store 或执行领域变更。资源条带实现 WAI-ARIA 标签页与可见的 roving 焦点。工具栏是
按下按钮的具名工具栏：方向键移动焦点，Enter/Space 激活，`aria-controls` 关联每个已存在的组。
工具主体是具名区域，终端主体是 tabpanel。折叠的辅助组在卸载主体的同时保留一个被关联的原
生隐藏区域；在没有标签页渲染时，它选中的边缘栏控件就是焦点端点。本地折叠会把焦点移到该控件，
展开则把焦点还给选中的标签页。分隔条暴露方向与当前/最小/最大值。`Ctrl+F6` 按视觉顺序访问
上排组，然后从左到右访问可见的底部组。

中心资源条带与辅助终端会话条带具有有界的可读标签宽度，没有固定的上一页/下一页控件：滚轮、
触控板、触摸、roving 键盘导航、活动揭示，以及可搜索的键盘溢出列表滚动的是同一个列表。原生
滚动条保持隐藏；指针透明的边缘淡出只在被裁切处出现，并在不改变固定 28 px 条带的前提下更新。
条带动作是共享的 `IconButton ghost m` 控件（24 px 方块，在条带中垂直居中），而不是整高的
单元格。控件只在能起作用时渲染：溢出搜索只在被裁切时出现；每个展开的辅助 pane 都有 Hide 动
作，因为它的工具栏仍可用于恢复。单例工具图标没有内联关闭字形；显式的 Remove tool from
group 留在它们的菜单与 Delete 上，与 pane 可见性分开。终端与中心资源保留直接的关闭控件。

外部关闭请求通过注入的 `subscribeCloseRequest` prop 到达；只有订阅之后的请求才计数，因此过
期的请求绝不会关闭标签页。聚焦的边缘栏选择器是导航 chrome，不是单个资源的关闭目标，并在回
退之前产生一次 no-op。内部纯函数 `closeRequestTarget` 选中 DOM 聚焦组的选中（否则第一个）
标签页，否则选最后聚焦中心组的；工具标签页、折叠组或隐藏区域不产生目标，也不再进一步回退。
工作台通过它正常的关闭路径路由该请求。

每个辅助 pane 头部或终端会话条带都尾随一个属于布局的"加到本 pane"菜单：终端或空 pane 上的
*New terminal* 会加到那个 pane，而工具 pane 提供 *New terminal pane below*，它直接在它之后
创建一个无工具的组并把终端放在那里（`onNewTerminal` 带 `newPaneBelow`；shell 不再注入侧边
菜单动作）。菜单还会列出对该区域有效的未放置工具；两条工具栏绝不会提供同一个单例。中心标签
页菜单不提供单例工具。从辅助组创建的终端会落在该工作区匹配的组里；消失的目标会通过当前本地
焦点规则改路由。菜单用内容来命名 pane ——`Move to right pane (Changes, Review)`，至多三个名
字然后 `+N`，没有内容时是 `(empty)` —— 绝不用 id，而标签页的菜单只列出永远可能对它生效的命
令：工具不携带仅限中心的项（keep 预览、四个分割），辅助终端不携带分割。

## 预置与本地持久化（Presets and local persistence）

Balanced、Focus 与 Review 是 web 拥有的、无资源的帧定义，带一个中心下方的底槽：Balanced 与
Review 显示它；Focus 隐藏它。Balanced 与 Focus 起始时有一个中心组；Review 提供它刻意的垂直
成对。Balanced 的右下组以 TODO List 打开，Review 在旁：在全新工作区里，计划才是可看的东西，
而评审意见只在有 diff 之后才存在。自定义预置使用同样的语法，并捕获几何、拓扑、工具、折叠
与空结构槽位，绝不捕获工作区资源或终端数量。预置节点 id 是模板本地的标签：实例化会铸造前端
本地的帧 id，并返回用于给每个工作区视图重新安家的旧→新组映射。只有自定义定义通过 settings
过线上契约；一个放置 TODO List（`plan`）的集合只在 `LAYOUT_PLAN_PRESET_PROTOCOL_VERSION` 或
更新的宿主上保存 —— 更旧宿主的校验器会拒绝该工具，因此 Layout 设置会解释这一点而不是发送它。
内置预置名是展示文案：`layoutPresetName` 按预置 id 经 locale 目录渲染它们，而定义保留它
稳定的 `name`；自定义预置名是用户数据，逐字渲染。

应用一个预置会创建一个替换帧，必要时提高这个表面的本地侧/底上限，并原子地重映射所有保留的
工作区视图。中心资源保持视觉顺序并分散到目的叶子；终端映射到兼容的槽位；单例工具放置 id 尽
可能存活。被省略的工具会得到确定性的恢复目标，因此稀疏预置无法把 Projects 或其他工具抛在一
边。本地默认预置是显式 Reset 帧命令的目标；普通工作区切换保留当前的帧。默认选择与上限持久
化在本地，不在宿主设置里。

`layoutState` 在浏览器 endpoint + 前端表面身份下，或在原生稳定适配器的 profile/window 作用
域下，校验并持久化归一化的帧/视图/注意文档。重载与受支持的会话恢复复用它；同时存在的窗口绝
不消费彼此的存储事件。持久化只包含引用。失败会让实时状态保持不变；未知 schema 回退到
Balanced 安全帧。

完整的当前布局语法，包括既有 shell 渲染器所消费的派生 `WorkspaceLayoutDocument` 投影，都是
web 本地的。原始表面会实例化 Balanced；不导入任何宿主快照或先前的布局 schema。

终端可见性门禁只为在某个已展开、可见组中被本地选中的终端挂载主体。不同的终端身份可以并发挂
载；一个身份在每个浏览器表面上只有一个主体。非活动/折叠/隐藏的标签页绝不附加。全局 New
Terminal 指向最后的本地底部焦点，只通过显式的帧命令创建帧槽位；中心 Group Header 的创建会
捕获那个组。宿主目录对账可以在本地放置一个尚未被表示的终端而不选中它，但不能改变帧几何。

## 渲染隔离（Render isolation）

工作台是一个挂载主体的宿主，因此渲染器要保护注入的功能主体免受排布变动的影响。根
`Workbench` 拥有所有瞬态视图状态 —— 拖动、尺寸投影、测量尺寸、关闭后焦点 —— 并拥有每一次注
意转换。组绝不修改注意：根向下传递稳定的、读 ref 的回调（`onSelectTab`、`onFocusGroup`、
`onApply`、`onFocusAdjacentGroup`、`onHideSide`、`onRevealTool`、`readAttention`），它们的
身份在文档与注意变化中存活，因此根的重渲染绝不会仅因身份而让子项的 props 失效。

那唯一的 `attention` 对象不会被穿进叶子。只有枚举组的区域包装（中心节点/分割、侧与底堆栈）
接收它，并把每个组的 `selectedId` 投影为原始值；叶子组视图接收那个原始值，绝不是整个覆盖层。
叶子组视图、标签条、标签页与堆栈都被 memo 化。由此得出两项隔离保证，它们就是渲染器的契约：

- 一次调整尺寸或拖动手势只修改根本地的投影状态；因为文档、注意与共享回调全都没变，被 memo
  的组子树不会重渲染，手势期间也没有功能主体重渲染。真正改变文档的那次指针抬起提交才是唯一
  的重渲染。
- 一个组内的选择或焦点变化只重渲染该组的 chrome；兄弟组保持各自的 `selectedId` 并跳过。每
  个挂载的标签页主体都位于以选中标签身份为 key、只依赖稳定 body 渲染器的被 memo 的
  `GroupTabBody` 边界之后，因此一个主体只在它自己的选中标签变化时重渲染 —— 绝不因为某个兄
  弟、一次调整尺寸或一次拖动发生重渲染。shell 宿主对编辑器标签页的缓存写入也保持这一点：文
  件/diff/变更主体在主体内部解析它自己的缓存标签页（`EditorResourceBody`），绝不通过渲染器
  的闭包，因此评审标签页的按键频率写入只重渲染那个主体
  （`e2e/perf/editorTabIsolation.perf.ts`）。

memo 化假设注入的渲染回调是引用稳定的：shell 宿主把 `renderTabBody`/`renderToolBody`/
`renderTabAdornment`/`renderEmptyCenter`/`renderCenterActions` 作为被 memo 的身份传入，因
此父级重渲染（例如一次注意变化）不会仅因 prop 身份就破坏兄弟组的 chrome memo。
`chatFirstPrompts` 是一个浅稳定的记录（shell 用 `useShallow` 选择它），因此它只在某个未命
名 chat 的标签变化时才改变身份。

`e2e/perf/layoutIsolation.perf.ts` 针对渲染 profiler 钉住这两条保证。

## 内部模块结构（Internal module structure）

渲染器是 `index.ts` 之后的一个子模块；它的文件都是内部的，彼此直接导入。`workbenchShared`
持有公开的 prop 契约（`WorkbenchProps`、`SharedGroupProps`、`LayoutTabFocusRequest`）、拖
放原语、尺寸/大小/溢出/结算钩子、DOM-id 辅助函数（组、标签页、工具栏组、工具栏控件），以及
共享的叶子原语（`DropZone`、`CenterSplitTarget`、`PanelWithHandle`、`GroupTabBody`）。
`workbenchTabs` 拥有标签条与标签页（包括标签页的工具栏模式）；`workbenchCenter`、
`workbenchSide`（也是两个边缘家族共享的 `AuxiliaryGroupHeader`）与 `workbenchBottom` 拥有
各自的区域视图家族；`workbenchRails` 拥有区域工具栏及其可放置的条目按钮；`tabIcon` 是唯一
的 Line/Fill 图标解析器，与 shell 的 Project Home 共享；`Workbench` 是组合它们并拥有状态的
根。工具栏是唯一从 `attention` 渲染（其条目的选中状态）的叶子，因此根像对待堆栈一样显式地
把覆盖层传给它，而它的激活则通过 `onApply` 与共享的 `onUserNavigation` 运行。`index.ts` 重
新导出组件、它的公开类型，以及 Project Home 所组合的工具栏/pane 头部原语。
