# shell/layoutState —— 前端本地的布局归属

> 中文译文，原文见 [`SPEC.md`](./SPEC.md)。英文原文是唯一权威来源，二者不一致时以原文为准。

## 职责（Responsibility）

拥有某一个前端界面的当前 workbench 状态：初始化那个唯一的无资源 frame，水合并持久化它按工作区的
views／attention 与本地布局偏好，并把原子的 frame 加 view 变更提交进 Zustand。

## 边界（Boundary）

- **拥有：** 带版本的本地文档与校验边界；浏览器端点／界面限定的身份与原生稳定 key 选择；净态的
  Balanced 初始化；水合与尽力而为的持久化生命周期；本地默认／上限偏好；安装纯 `layout/` 结果的
  原子提交助手；以及工作区清理。
- **公开接口（`index.ts`）：** 挂载的水合／持久化 hook、本地布局提交与工作区初始化入口、界面状态
  就绪态，以及供测试使用的确定性存储接缝。
- **外部依赖：** 浏览器存储／会话原语、带 `BroadcastChannel` 占用探测回退的 Web Locks、可选的
  稳定字符串偏好适配器、React、用于浏览器端点身份与错误归一化的 `transport`，以及仅为同步
  `LayoutPreset` 类型而用的 `@thinkrail/contracts`。
- **禁止：** 任何当前布局请求或推送；乐观的修订／冲突队列；功能渲染；领域资源生命周期；导入
  server/shared/pi；读取旧宿主快照或旧浏览器 attention key；或把浏览器存储调用放进 Zustand store。

这份实时状态属于某一个浏览器标签或原生窗口。浏览器 key 由 transport 端点与一个可在会话间恢复的
界面 id 限定。在读取该 key 之前，浏览器通过一个源内 Web Lock 为这份实时文档声明该端点／id，并以
有界的 `BroadcastChannel` 占用探测作为回退。一个已被另一个活动标签声明的复制 id 会被重新生成，
并写回该克隆的 session storage；重新加载会释放并重新获取同一个 id。声明通道只承载身份探测 ——
绝不承载 frame 或工作区状态。没有原生适配器时，浏览器的端点／界面加锁与存储行为保持不变。

原生适配器本身已由 `{ backendProfileId, windowId }` 限定，因此 `layoutState` 经它读写一个固定的
布局 key，不并入当前 transport 端点，也不声明浏览器界面。它序列化完全相同的带版本文档，并运行与
浏览器路径完全相同的解码器：不存在跨宿主的布局同步，也不存在原生专用迁移。超过 256 Ki 字符的
序列化文档会作为一次持久化失败被拒绝，而不是分块或部分写入；实时 frame 仍可用，原生适配器保留其
1 MiB 总量保护。

即使停留在 Welcome、尚未打开任何工作区，shell 也会初始化这份状态，因此本地默认／上限的编辑立即可
持久化。缺失、无效或来自未来版本的本地文档直接从 Balanced frame 开始。此前持久化的宿主快照与旧的
attention 条目保持原样且惰性。并存的多个界面永不消费彼此的存储事件。持久化失败后实时状态仍可用。

新打开的工作区获得一个经由该界面当前 frame 投影出的空本地 view；当本地 frame 已完成水合时，这在
一次 layout effect 中同步发生，只有水合之前的路径会等待。空 view 投影是一个公开的纯推导，由安装、
frame 校验与 workbench 的安装前渲染共用，因此安装前渲染出的结构与最终安装的结构完全一致。该投影
采用最近活动的保留工作区的工具选择，并且每次本地 attention 写入都会把新选中的工具在同一事务中扇出
到其他保留的 view；而一次归一化结果与已存 attention 相等的 attention 写入（焦点事件落在已选中的标签
上、一次重选）会在到达 store 之前被丢弃，因此它无法触发 workbench 重渲染；一次 frame 提交会把提交
方 view 的工具选择重新应用到每个被重投影的 view 上。这些都不会替换任何 view 选中的资源。改变 frame
形状的 frame 命令会推进一个由所有工作区 view 共享的 frame 级投影 epoch；仅几何的提交（侧宽、底部
高度、组与分割权重）永不推进。该 epoch 是手势围栏，不是重挂载 key：workbench 用它取消一个基础形状
已在其下方消失的拖拽或键盘调整，而面板组与资源主体在形状变化中保持挂载。普通的工作区切换同样不会
改变它；宿主领域水合随后只填充该界面显式打开或被动拥有的资源，例如它确定性的初始终端。一次 frame
变更与所有必需的 workspace-view 重映射是一次 store 事务和一份持久化的本地文档。被投影的回调携带其
渲染基础，并可携带完整的最终 attention；过期回调只把它实际改动过的顶层区域重基到最新投影上，因此
嵌套的调整／布局效果无法回退较新的区域。文档与 attention 的变更通过一次 `applyLocalLayoutState`
调用一起发布，包括单例扇出；交互式调用方在 frame 提交之前永不持久化一个中间态的仅 attention 状态。
可选的终端召回会针对存活的组成员关系做归一化，并保持在单个工作区之内。没有它的旧版本 1 文档仍然
有效；畸形的召回被独立丢弃，而不是重置一个本来有效的 frame。关闭资源只改变它所在工作区的 view。
空的 frame 组会保留。显式的组移除／合并与预设应用可能改变拓扑，因此它们的纯结果包含对每个保留工作区
view 的确定性重映射；提交之后任何 view 都不得引用已被移除的组。
